The 146-trial basin-hopping study did **not** fail to find min 18/19 on the user's real workbook.
It never saw that workbook.

Cloud agents only have git remote `main` at `f9459f4`. That tree does **not** contain `heavy_maintenance_forecast.xlsx`. The previous study (`bc-06aed119-038e-4ffa-bc9a-b92863a71dc0`) regenerated a *different* 24-aircraft / 12-year instance with `generate_extended_dataset.py`. On that file the frozen hill-climb already stops at **min 16**. Every SA trial warm-started from that 16-opt and returned min 16.

The user's baseline-18 claim is about a **different local workbook** that is not in git.

## How the cloud forecast was created

`generate_extended_dataset.py`:

1. Reads first-start dates from `Simple Random Fleet Plans.xlsx` sheet `MxEvents` (10 Blue aircraft).
2. Pads the fleet to 24 with `Aircraft 11`…`Aircraft 24` using `np.random.seed(42)` and random offsets in `[0, 730)`.
3. For each aircraft, builds an A/B/C/D due-date schedule and places **each check at a random day inside its legal window**.
4. Writes sheet `MxEvents` plus Availability / Fleet / CheckRules / Summary.

That is a random feasible 12-year instance, not a saved local workbook. Even with seed 42 it will not match a file that was generated by an older generator, later edited, or saved after a local optimisation.

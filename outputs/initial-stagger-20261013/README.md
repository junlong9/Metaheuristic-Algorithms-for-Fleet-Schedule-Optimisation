# Maintenance-age stagger input forecasts

Two synthetic input forecasts use the same 24 aircraft, the same forecast from
21 January 2026 through 18 January 2038, and the same maintenance rules as the
original heavy forecast. Their initial maintenance ages are different, so D
checks naturally fall earlier. They are input datasets, before optimisation.

| Measure | Original input | Moderate stagger | Wide stagger |
| --- | ---: | ---: | ---: |
| Earliest first forecast D start | 6 Dec 2032 | 23 Jan 2028 | 8 Mar 2027 |
| Aircraft with first forecast D before 2030 | 0 | 9 | 11 |
| Peak simultaneous D checks | 9 | 6 | 4 |
| Worst-day availability | 15 | 16 | 17 |
| Availability standard deviation (sample) | 1.954 | 1.717 | 1.412 |
| Mean availability | 21.680 | 21.478 | 21.488 |
| D checks intersecting the forecast | 24 | 31 | 33 |
| Maintenance aircraft-days within the forecast | 10,166 | 11,049 | 11,004 |
| Existing loose / medium scenarios | Pass / Pass | Pass / Pass | Pass / Pass |
| Existing tight scenario | Fail | Fail | Fail |

## Rules and generation

The moderate input has three cohorts of eight aircraft, with their source
maintenance timelines advanced by 1, 3 or 5 model years. The wide input has six
cohorts of four aircraft, advanced by 1 through 6 model years. One model year
is 365 days, matching the existing interval definitions. Cohort membership is
assigned once using NumPy seed 42, without selecting for better availability.

This advance changes the hypothetical maintenance state at the start of a new
input dataset. It is not an optimiser move from the original input. Existing
checks, their due dates, and their start windows are translated together.
Later required checks are generated by replaying the same fixed A/B/A/C/A/B/A/D
sequence and completion-based reset intervals. No early-D experimental policy
or replacement of smaller checks is used.

Durations remain A=14, B=28, C=84 and D=126 days. Intervals remain A=365, B=730,
C=1,460 and D=2,920 days. A checks retain their 42-day early-start allowance.
B, C and D checks retain their 70-day allowance. Every check remains within
its own start window; the maximum D earliness is 70 days. Checks do not overlap
on the same aircraft. Full durations are retained for checks crossing the end
of the forecast, and daily counts include only days within that common horizon.

All operational scenario dates, availability requirements, dependency groups,
and displacement limits are copied unchanged. These inputs pass the loose
and medium scenarios. The tight scenario's dependency requirements fail and
are reported without relaxation. Each input is its own as-loaded reference:
subsequent optimisation must enforce the existing 70 / 42 / 21-day displacement
limit for the chosen scenario, including movements caused by a rebuild.
Neither new input is claimed to be a legal displacement of the original input.

## Maintenance state and use

Both workbooks now match the original heavy forecast's exact five-sheet
structure and order: MxEvents, Availability, Fleet, CheckRules, Summary.
Column names, header formatting, cell formats, sheet layout and the native
availability line chart are preserved from the original file. Fleet contains
only Aircraft and First_Start, and Summary uses the original seven metrics
and sample variance / standard-deviation convention. Values are saved snapshots,
matching the source workbook. Editing checks does not regenerate the forecast.

The additional history, opening due clocks, sequence positions, age since D,
and operational audit remain in `.scratch/initial-maintenance-stagger/schedule-data.json`
and `validation.json`, outside the Excel files. The initial reset assumption is
inherited from the source model: the opening A due date is one model year after
a hypothetical preceding D completion. These histories and ages are synthetic.

The current priority optimiser's rebuild assumes each aircraft starts with the
opening A check and reconstructs its D clock from that check. An aged fleet can
start at another sequence position, so these workbooks need an adapter that
reads the saved opening clocks and sequence position before optimisation.
Simply changing FILE_PATH in that optimiser will not preserve the intended
maintenance ages. The original optimiser and its defaults were not changed.

## Interpretation

This is a sensible direction for investigating whether initial fleet maintenance
ages cause D-check bunching while retaining the maintenance rules. It is related
to the initial-stagger idea, but the project's existing controlled start-schedule
experiment keeps the same checks and initial due dates. These new inputs instead
test sensitivity to different initial maintenance ages.

The lower D overlap and improved worst-day availability are properties of these
new input fleets. They do not show that an optimiser improved the original
forecast. Older aircraft can reach a second D check before the forecast ends,
which explains the higher check count and slightly lower mean availability.
For a fair method comparison, run both methods on each input with its own frozen
initial state, a common horizon, and the same constraints and settings.

Both saved workbooks were independently checked against the unchanged baseline's
maintenance replay, including the historical checks. Their daily counts, formula
counts, durations, legal windows, sequence positions and opening ages were
validated. The original heavy workbook and operational configuration hashes
remain unchanged. All template parts outside the changed data cells and chart
value cache were compared with the source, including the styles and drawing
anchor. The native chart's series, axes, dimensions and formatting are unchanged.

Reproduction scripts and detailed validation are in
`.scratch/initial-maintenance-stagger/`: run `build_data.py`,
`match_reference.mjs edit`, `preserve_template.py`, then `validate_outputs.py`.
The earlier `build_workbooks.mjs` is the superseded expanded-layout builder.
